PERFORMANCE - NUMBA (measured on this repo, see notes below)
PF-01 S  Kalman smoother (analysis/smoothing.py _kalman_smoother_1d): scalar
         loops, 117 ms -> 4 ms for 100k points (x29). @njit(cache=True) kernel
         on float64 arrays; validation stays in the wrapper.
PF-02 S  Nelson rules (analysis/control_charts.py find_violations): 71 ms at
         5k points, 1.5 s at 100k (windowed Python loops). Compiled kernel
         returns one bitmask per sample (one bit per rule 2-8); Violation
         objects and descriptions are built in Python afterwards.
PF-03 S  Without Numba: Whittaker-Eilers (banded/sparse solver instead of the
         dense np.linalg.solve - O(n^3) now), cluster-label remap
         (np.unique return_inverse), contingency/mosaic (integer codes +
         np.bincount), linear root crossings (direct computation), wavelet
         power (batch scales), correlation (scipy FFT correlate).
PF-04 M  Batch Monte Carlo scoring - only if the whole scoring kernel can be
         compiled; otherwise skip. Survival: improve the algorithm first.
Rules: Numba stays an OPTIONAL dependency with a pure-Python fallback; cache=True;
compile in a kernel only numeric arrays (no dataclasses, dicts, closures).
Not worth it: multi-peak model (already vectorised: 0.2 ms for 5 peaks x 2000
points; Jacobian 7 ms for 21 parameters - a fit of 50 iterations is well under
a second) and model-specific Jacobians (they need the whole chain compiled:
model -> residual -> perturbation -> Jacobian; large effort, small gain).
Never target: Qt panels, Matplotlib rendering and style editing, pandas,
statsmodels, scikit-learn, SciPy wrappers, string/SQL/catalogue logic.
