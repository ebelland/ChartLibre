ChartLibre Developer: one launcher for the contributors' tools (2026-11-07)
==========================================================================

What it is
----------
dev/ChartLibreDeveloper.py, run with venv/bin/python dev/ChartLibreDeveloper.py: a window like the Project page -
titled frames, each a button with its sentence under it - grouped in three columns. It uses the app's own style
(apply_platform_style, NavPanel, NavButton), so it looks like ChartLibre. Not in the packaged app.

 Write code                  Check                               Ship
 --------------------------  ----------------------------------  -------------------------------------------
 Edit localization           Run the tests -> report             Build the bundle (.dmg / .zip)
 Data operation creator      NIST report                         Update Python and libraries
 Function creator            Project size (appsize.csv chart)    Compile the user manual (Typst -> PDF)
 Renderer creator            Make chart previews                 Developer manual (DEVELOPMENT.md)
 Qt style editor (new)

A. The launcher and the four dialogs moved: app/developer_helpers/ -> dev/developer/ (localization, data operation,
   function, renderer helpers and their base). The Project page keeps project info, history, database, log; its
   developer frames, Settings' "Developer mode" and _apply_developer_mode go. The 4 imports leave main_window.
   Tests (test_scaffold_dialogs, test_machine_translation) follow the move.

B. Long scripts (tests, bundle, dependencies, manual, previews, NIST) run as a subprocess in a log pane with Stop,
   one at a time - never two test runs at once. Each ends with a line: done / failed, and the file it made
   (Open / Show in Finder).
   - Tests: pytest -n 6 with --junitxml; the report shows passed / failed / skipped and each failure's message,
     its file:line clickable (opens in the editor). Options: all, or the files changed since the last commit.
   - Project size: the appsize.csv rows as a small chart (lines of code and files per commit) and today's count.
   - Update Python and libraries: what update_dependencies.py does, with the pins shown before and after and
     the test run offered afterwards; nothing written without a confirmation.
   - Manual: typst compile docs/manual/user_manual.typ; says if typst is missing and how to get it.
   - Developer manual: dev/DEVELOPMENT.md rendered (QTextBrowser Markdown), with a link to open it in the editor.

C. Qt style editor (new, small): pick one of app/styles/*.qss, edit it with search, the @TOKENS@ listed with their
   values, Apply previews it live on a sample of the app's widgets (buttons, combo, table, the chart pill, a
   titled card) in light and dark; Save writes the file (a .bak kept). No new style format.

D. Clean-up, after A-C pass:
   - files no longer used: dev/tools scripts the launcher replaced only if their logic moved (the .bat/.command
     wrappers of update_dependencies stay if they are the user's way in); stale screenshots in dev/test_results.
   - unused functions and imports across app/: vulture (min-confidence 80) and ruff F401/F841, each hit checked
     by hand before removal (plugins, Qt slots and catalogue names are found by name, not by import).
   - the size before and after in todo.txt.
   A list of what goes is shown before deleting anything.

E. main.py becomes ChartLibre.py (git mv, history kept). 13 files name it: the macOS launcher in ChartLibre.app and
   its generator make_launcher.py, ChartLibre.sh, build_bundle.py, the Windows launcher's C source, README,
   DEVELOPMENT.md, comments, and the installer and Python-support tests.
   ChartLibre.exe is a compiled launcher with "main.py" inside: it must be rebuilt from chartlibre_launcher.c
   (MinGW or MSVC, on Windows or cross-compiled). Until it is, a main.py of three lines stays beside ChartLibre.py
   and runs it, so an existing Windows install and an old .exe keep starting; it goes once the .exe is rebuilt.

Strings: the launcher is for contributors and stays in English, not translated. Removed strings (Developer mode)
are listed so the .po files can drop them.

Risks
- Plugins written by users with the helpers already made are untouched; only the helpers move.
- vulture reports false positives on Qt overrides and names looked up by string: nothing is removed without a
  grep for its name.

Order: E (small, first) - A - B - C - D, one commit each; the suite run after each.
