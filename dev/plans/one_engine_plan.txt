ONE ENGINE: THE TABLE OPERATIONS INTO THE SERIES (DATA) OPERATIONS - PLAN                         2026-10-30

WHAT WAS ASKED
"Unico motore per series e table operations. Sposta tutto in series operations."

WHERE IT STANDS
- Already ported as real data operations (one series at a time, report-only or drawn from SQL values):
  Distribution, Is it normal?, Has it changed over time?, Clustering (the uploaded dialog and math).
- Still table operations (app/table_operations, 15): Are there differences?, What has the most impact?,
  Is it in control?, Cluster Table, Discriminant, Factor Analysis, Fit Model, Fit Y by X, Gage R&R,
  Multivariate, Partition, PLS, Principal Components, Time Series, Vector Field.
  They read several columns in roles (group, factor, time, X list) - the data engine reads a series' x and y.
- Shared already: AnalysisDialogBase (report figure, preview savepoints, draw_on), OperationShell (window,
  Charts tab, Draw on, history), report_html, reading_guide, next_steps.

STAGE 1 - ONE FAMILY (this step)
1. The table operations' files move to app/data_operations; their base classes to
   app/plugin_api/data_operations (roles_base.RolesOperationDialogBase, quick_answer.QuickAnswerDialogBase).
2. One scanner: the data operations' family finds classes on DataOperationDialogBase, RolesOperationDialogBase
   and QuickAnswerDialogBase; each entry says which base it is on ("base"). table_operation_scanner goes.
3. The Analysis panel, the catalog, the AI tools and the main window read the one list; an operation on the
   roles base opens on the table selected, its columns cast; the others on the current chart.
4. Imports in the tests and demos follow; the suite green.

STAGE 2 - ONE BASE (done)
RolesOperationDialogBase is a DataOperationDialogBase: the same window (_build_common_ui, its tabs, Revert,
the Charts page), the same Preview / OK / Close path (preview -> _run_operation, ok -> apply -> accept,
discard_unapplied). What it adds is the Data page (the ColumnRolesWidget, now a plain page; the operation's
own pages through input_pages) and its _run_operation: compute(frame, casting, params, model) on a worker,
apply_results inside the preview's savepoint, or for good with its undo step and history record.
The plugins' contract (compute, report_body, apply_results, build_extra_inputs) is unchanged.

STAGE 3 - EACH ANALYSIS AS A SERIES OPERATION WHERE IT IS ONE (done)
Is it in control? reads each series as Has it changed over time? does: its x orders the values, its y is the
measure; the limits and the signals are drawn as values, no table is written (the line drawing is shared in
quick_answer: points_query, measured_query). A table's column still opens it ("What next?" from Is it normal?),
read as its series. Time Series keeps its roles: its X input and its intervention are columns of a table, and
"Data from: Chart" already reads a chart's series for it, as for every analysis on roles.
