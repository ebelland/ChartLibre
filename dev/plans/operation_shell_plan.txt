WHAT IS THERE TODAY
- Data operations (19, app/data_operations) derive from DataOperationDialogBase (a mixin package of 8
  modules: layout, inputs, evaluation, results, transaction, hooks...). Data = the chart's series (or a
  table's columns); Preview draws inside a savepoint, OK keeps it. Where the result goes is decided per
  operation: 5 declare a "destination" parameter (Function, Calculus, Transform, Regression, GP), the others
  hard-code it in resolve_target_axis_id (Fit: the source axis; Control Chart: a new axis...). What is drawn
  is scattered: Fit's bands and extra charts in its Output tab, Control Chart's draw_limits/zones/signals in
  Parameters, others fixed.
- Table analyses (19 + 5 quick answers, app/table_operations) derive from TableOperationDialogBase, a
  QDialog of its own: Data = column roles, Parameters, a report pane; computed in the background; no
  Preview of a chart - OK writes tables and makes a new report figure (create_report_figure, panels).

THE PROPOSAL - ONE SHELL, TWO KINDS OF DATA
A literal "Distribution derives from DataOperationDialogBase" would drag the series machinery (series
selector, per-series results, result tables per series) into analyses that read whole tables. Instead:

  OperationShell (new, app/plugin_api/operation_shell/)  - the window both kinds share:
      tabs (Data | Model | Parameters | Charts | extra), results pane, buttons (Preview, Revert, Copy, OK,
      Cancel, Stop), background run with Stop, preview savepoint and its rollback, the Charts tab,
      failure shown in the results pane, undo step on OK.
  DataOperationDialogBase(OperationShell)   - Data = series selector / table columns (as now).
  TableOperationDialogBase(OperationShell)  - Data = column roles (as now); compute(frame) unchanged.

So every plugin keeps its own contract (compute / compute_results / apply_results); what changes is the
shell around it. Both kinds then have the same tabs, the same Charts tab and the same Preview.

THE CHARTS TAB (2.)
- "Draw on": ( ) Current axis   ( ) New axis in this figure   ( ) New figure   - each operation declares
  which it allows and its default (DESTINATIONS, DEFAULT_DESTINATION class attributes); the 5 "destination"
  parameters and the hard-coded choices move here. A table analysis (no current axis of its own) offers
  New figure (default) and New axis in the current figure.
- "Charts": a check box per chart the operation can draw, declared by the plugin:
      CHARTS = (ChartOption("curve", "Fitted curve", default=True), ChartOption("ci", "95% confidence band"),...)
  read with self.chart_enabled("ci"). Moved here: Fit's bands and extra charts, Control Chart's limits /
  centre / zones / signals, Distribution's histogram / Q-Q plot / box plot / CDF, Fit Model's
  actual-by-predicted / residuals / profiler, and so on for each analysis.
- The choices are recorded with the operation (todo R-03), under the keys the parameters have now, so
  saved projects re-run the same.

PREVIEW FOR THE TABLE ANALYSES (3.)
- Preview computes, writes the result tables and draws the checked charts where "Draw on" says - inside the
  preview savepoint, like the data operations; Revert or Cancel rolls it back; OK keeps it (one undo step).
- apply_results(result) keeps its role; create_report_figure learns the destination (a new axis in the
  current figure as well as a new figure) and draws only the checked panels.

DISTRIBUTION (3.)
- Model tab: "Distribution" - Normal (default), Lognormal, Weibull, Gamma, Exponential, Best fit (AIC),
  from app/utils/distribution_fit (it already fits these). The histogram's overlay, the probability
  (Q-Q) plot's reference and a goodness-of-fit table (Kolmogorov-Smirnov, Anderson-Darling, AIC) follow
  the choice; the parameters of the fitted distribution in the report.
- Charts tab: Histogram with the fitted density, Q-Q plot against the chosen distribution, Box plot, CDF.
