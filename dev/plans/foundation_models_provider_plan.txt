Apple Foundation Models: an assistant provider on this Mac's own model (2026-11-07)
====================================================================================

What was tried on this Mac (Apple Silicon, macOS 27, Command Line Tools, no Xcode)
---------------------------------------------------------------------------------
- Python SDK (apple-fm-sdk 0.2.1): only a source package, which needs Xcode to build; its install failed
  here on Python 3.15. It is also a beta, documented for 3.10-3.12.
- A short Swift program, run with the Command Line Tools alone: the model is "available" and answered a question.

Proposal: a small Swift helper instead of the Python SDK
--------------------------------------------------------
No Python package, no Xcode, no wheel to wait for. The provider talks to one helper process per conversation,
JSON lines on stdin and stdout; the same pattern as Ollama's stream, without the network.

 app/ai_providers/foundation_models_provider.py   the provider (AIProvider, ChatSession)
 app/ai_providers/foundation_models_helper.swift  the helper's source, about 150 lines

A. The helper. Built with swiftc on first use into the user's cache folder, rebuilt when its source changes.
   Messages: start(instructions, tools) - user(text) - tool_results; back: text, tool_calls, done, error.
   Each ToolSpec's JSON schema becomes a DynamicGenerationSchema. Swift's tool runs inside respond(): its call
   writes tool_call and waits on stdin for the result.
B. The provider. send() returns Turn(stop="tools") when a tool_call arrives and the next send() hands the results
   back to the waiting call, so the application's confirmations and Undo stay as they are. Stop cancels the task.
   SENDS_DATA = False. One model: classify() is always ACCURATE. No token counts unless the API gives them.
C. unavailable() says why, in words to act on: not a Mac, macOS too old, no swiftc (xcode-select --install),
   Apple Intelligence off, the model still downloading.
D. Errors: the context exceeded says to start a new conversation; a guardrail refusal is stop="refused".
E. The small context. To verify first, in A: the limit is not in the SDK's docs (about 4096 tokens as far as
   I recall). The nine tools take about 1000 tokens and the analyses catalogue about 3500; a tool result may be
   8000 characters. So a provider may ask for less: results cut shorter, and the catalogue by names only with
   detail on request. Claude and Ollama keep what they have.
F. Tests: the JSON protocol and the mapping to Turn against a fake helper script (never the real model), so the
   suite passes on any machine. Settings shows the provider; Windows and Linux report it as unavailable.

Risks
-----
- Whether a real multi-step analysis fits the small context, and how well this model picks tools. Measured live
  after A and B with the steps used for Ollama, before E is designed in detail; if it is poor, the provider ships
  as read-only questions (list, describe, query) rather than analyses.
- swiftc needs the Command Line Tools. A prebuilt helper in the packaged app would need signing: not in this plan.

Order: A, B (live test) - C, D - E - F. New strings are listed for translation, not translated.
