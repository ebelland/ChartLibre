__queries__ and __sympy__: one logic for the project's two stored sources (2026-11-03)
======================================================================================

Both are rows the Tables list shows beside the tables (kind "query" / "function"),
both are a data source (DataSource.from_clause inlines their SQL), both are
deleted from the same menu. Today they are handled in two different ways.

Proposal (one commit each, tests after each)
--------------------------------------------
A. One place creates and migrates both tables: at open (_ensure_project_tables), not in
   every call. list/get/save/delete of __sympy__ stop calling create_sympy_table.
B. A StoredFunction dataclass beside SavedQuery (name, source_type, symbols, code, x/y
   ranges as GridRange, description, values as dict). get/list return it; the dict form
   (sympy_store's data) stays at the edges that serialise it (function_dialog, trust
   fingerprint) through to_dict()/from_dict(), so the fingerprints stay the same.
   The table's columns are NOT renamed: existing projects keep opening as they are.
C. Writes the same way: save_query and delete_query go through _commit() like the
   function ones (a Preview's savepoint then holds them too).
D. One namespace: next_source_name(stem) - free of tables, queries and functions,
   case-insensitive - used for "Query n" and "Functionn"; saving a query or a function
   under a name another source has is refused with a message, as a table's already is.
E. Rename for both from the Tables list: rename_query(old, new) and
   rename_function(old, new), which also rewrite the series that name them (as
   rename_table does for tables); the function's trust follows the new name.
F. Delete says what it breaks: before deleting, the series that read the query or the
   function are counted and named in the confirmation ("2 charts read Line: they will
   be empty").

Not in this plan: Undo for queries and functions (separate, it needs the descriptor
snapshot to cover the two tables); the column names.

Order: A, C (small, no behaviour change) - B - D - E - F. Strings added in D, E, F are
listed for translation, not translated.
