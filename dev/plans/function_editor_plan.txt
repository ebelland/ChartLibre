ONE FUNCTION EDITOR - IN CHART PROPERTIES' SERIES AND IN FUNCTION - PLAN      2026-10-27, go given (the direction below)

WHAT WAS ASKED
Chart properties > Series: let the function of a function series be edited. Option 1: a collapsible section
with the function's expression / code and its ranges. Better: one class, used there and in Function.

TODAY
- A function series is a live query: SELECT "x" AS "x", "y" AS "y" FROM (<function_sql>) AS "_src", the
  function by name, this chart's parameter values (JSON) and its x / y range written in it; the formula is
  read from __sympy__ at each draw.
- Series shows that query as text: the numbers can be edited only by hand, in SQL, and the formula not at all.
- The same things are edited in three places, three ways: Function (Expression / Code pages, the Parameters
  table, the ranges on its Charts tab), New Chart (FunctionSourcePanel: parameters and ranges).

THE CLASS: FunctionEditor (app/widgets/function_editor.py) - a QFrame with three tabs
Given the function (a __sympy__ row) and, for a series, its own values and ranges:
  Formula     Expression or Code: description, parameters (an expression's), the text. Checked as text (ast),
              never run to be checked (todo ID47).
  Parameters  One row per declared parameter, its value - the rows made from the declaration each time, never
              kept apart from it (the empty Parameters table cannot come back).
  Range       x: from / to / points / spacing; y the same, shown only when the formula uses y.
  load(function, values=None, x=None, y=None); function_data() (what sympy_store.save takes); parameters();
  x_range(); y_range(); ndim() (read, not run); show_formula(bool) (New Chart hides it); signal changed.

WHERE IT GOES
A. Series (Chart properties): a collapsible "Function" card, shown only for a function series, closed by
   default, under Properties.
   - Loaded from the stored function and from this series' query (its values and ranges read back from the
     SQL function_sql wrote: function_sql gains its inverse, parse_function_sql).
   - Apply (a button in the card): the formula is saved to __sympy__ - every chart of the function follows
     (the card says how many other series draw it); this series' values and ranges rewrite its own query
     only. One Undo step ("Function of 'X'"), as S-01's.
   - A function this computer does not trust: the card shows its code read-only, with Trust... (ID47).
B. Function: its Expression and Code pages become the editor's formula part, its Parameters tab the editor's
   values for them (the Library keeps its own table), its ranges the editor's ranges. The Stored bar stays.
C. New Chart: FunctionSourcePanel becomes the editor with the formula part hidden (values and ranges).
